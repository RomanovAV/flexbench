# FlexBench

Наш набор задач и обвязка для **Harbor + GigaCode CLI**. Harbor установлен как зависимость `harbor==0.24.0`; его исходники не изменяются. GigaCode запускается автоматически на рабочей машине, где он уже установлен и авторизован. **Контейнеры не используются.**

Модели, задачи и повторы выполняются параллельно в пределах `--concurrency` (по умолчанию 4). Каждая попытка получает отдельный каталог и Git-репозиторий. Harbor управляет очередью, тайм-аутами и результатами; автоматические retries отключены.

## Установка

Нужны Python **3.12+**, Git и установленный GigaCode в `PATH`. Для JS-задач нужен Node.js, для Java — JDK 17+. Docker, облачный аккаунт и отдельный API-ключ Harbor не нужны. Используется существующая авторизация GigaCode и его обычные настройки.

В корне репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
gigacode --version
```

Зависимости скачиваются при установке. Корпоративный индекс пакетов/прокси настраивается обычными средствами pip. Python 3.9 поддерживается только прежним runner; для нового запуска нужен 3.12+.

## Первый запуск

В одном терминале откройте интерфейс результатов:

```bash
source .venv/bin/activate
python -m flexbench harbor view --output artifacts/harbor
```

Откройте напечатанный адрес (по умолчанию `http://127.0.0.1:8080`); оставьте команду работающей. Это штатный локальный viewer Harbor. Другой порт: `--port 8081`.

Во втором терминале получите актуальные ID моделей и запустите небольшой тест:

```bash
source .venv/bin/activate
python -m flexbench models
python -m flexbench harbor run \
  --models DeepSeek-V4-Flash-0731 Qwen3.8-Flash-Next \
  --case js-retry-state --repeat 1 --concurrency 2 \
  --output artifacts/harbor
```

Замените ID, если каталог изменился. Это две независимые попытки, которые могут работать одновременно. Без `--models` GigaCode использует модель из профиля либо текущих настроек CLI. Каталог моделей читается отдельно через ACP без отправки задания модели.

Полный набор (8 задач × 2 модели × 2 повтора = 32 попытки):

```bash
python -m flexbench harbor run \
  --models DeepSeek-V4-Flash-0731 Qwen3.8-Flash-Next \
  --case all --repeat 2 --concurrency 4 \
  --output artifacts/harbor
```

`--concurrency` ограничивает количество одновременных попыток во всём прогоне. Отдельного последовательного режима и группировки выполнения по моделям нет. Фактический порядок начала попыток определяет Harbor. Большое значение увеличивает нагрузку на машину и API.

Проверить входы без вызова модели:

```bash
python -m flexbench harbor run --case js-retry-state --dry-run
```

Команда проверяет установленный GigaCode (`--version`), runtime выбранных задач, сохраняет задачи и валидирует конфигурацию Harbor. Она не проверяет доступность модельного API. Можно использовать напечатанный `config.json` напрямую: `harbor run --config /полный/путь/config.json`.

## Результаты

В `artifacts/harbor/` создаются:

| Путь | Содержимое |
|---|---|
| `gigacode-…/config.json` | Конфигурация Harbor с моделями, параллельностью и лимитами |
| `gigacode-…/inputs.json` | Версии Harbor/GigaCode/runtime и хеш профиля |
| `gigacode-…/tasks/` | Снимок условий, исходных файлов и оценщиков |
| `jobs/gigacode-…/` | Штатные результаты Harbor, доступные в viewer |
| `jobs/gigacode-…/flexbench-report.md` | Краткий отчёт об успешности |
| `jobs/gigacode-…/flexbench-summary.json` | Сводка времени, токенов, стоимости и покрытия измерениями |
| `jobs/gigacode-…/<попытка>/local/workspace/` | Итоговые файлы конкретной попытки |
| `…/<попытка>/agent/` | Поток GigaCode, stderr, причина завершения и измерения |
| `…/<попытка>/verifier/` | Проверки, reward и patch отслеживаемых файлов |

В viewer можно смотреть состояние прогона, попытки и файлы логов. В этой интеграции сохраняется родной `stream-json` GigaCode; преобразование в интерактивную ATIF-траекторию пока не реализовано. Markdown/JSON-сводки создаются обвязкой по завершении `flexbench harbor run`; прямой `harbor run --config …` сохраняет штатные результаты Harbor.

`reward` равен 1 только при прохождении всех проверок **и** нормальном завершении GigaCode. Отдельный `functional_pass` показывает, прошли ли проверки сохранённые файлы, в том числе после API-ошибки или тайм-аута. Код CLI: `0` — все попытки успешны; `1` — есть неуспешные попытки; `2` — ошибка настройки; `130` — прерывание. При прерывании смотрите сохранённые результаты Harbor; итоговая сводка обвязки может отсутствовать.

Токены берутся из единственного финального события GigaCode; промежуточные значения не суммируются. Без финального usage измерение неизвестно. Стоимость рассчитывается только по заданному тарифу. Настройки `pricing`/`pricing_by_model` прежнего профиля поддерживаются; сумма в USD передаётся Harbor, другие валюты сохраняются в `measurements.json` и нашей сводке. Полные суммы в `flexbench-summary.json` доступны только при полном покрытии; `observed_total` — известная часть. Штатные суммы Harbor могут отражать только доступные измерения.

## Конфигурация и ограничения

По умолчанию используется [profiles/gigacode-command.json](profiles/gigacode-command.json). Другой native-профиль: `--profile PATH`. Поддержаны executable, модель, timeout, approval, allowed tools, дополнительные инструкции и тарифы. Лимит GigaCode — 600 секунд из профиля. Адаптер не меняет корпоративные политики и не повышает разрешения после отказа.

Локальное окружение — расширение Harbor через `BaseEnvironment`, адаптер CLI — через `BaseAgent`, оценщик — через `BaseVerifier`. Они предназначены для задач FlexBench; произвольные контейнерные задачи Harbor здесь не поддерживаются. Пакет Harbor не патчится. Необязательная телеметрия Harbor и загрузка каталога цен LiteLLM по умолчанию отключены в обвязке.

**Локальные каталоги не создают границу безопасности.** GigaCode сохраняет доступ к файловой системе и сети текущего пользователя, его глобальным настройкам и авторизации. Оценщики и контрольные реализации не копируются в workspace, но агент технически может прочитать соседние каталоги. Запуск предназначен для доверенных задач в разрешённом рабочем окружении. При параллельных CLI-процессах общие настройки/авторизация GigaCode остаются общими; совместимость конкретной версии нужно подтвердить на целевой машине.

## Набор задач

| ID | Проверяется |
|---|---|
| `java-nearest-activity` | Выбор активности, фильтры и границы времени |
| `js-retry-state` | Состояния повторной операции, устаревшие ответы |
| `maven-version-alignment` | Согласованность POM и наследование версии |
| `java-task-reset` | Права, optimistic version, идемпотентность |
| `java-recommendation-rules` | Составные правила, квоты, версии и порядок отбора; v2, 24 проверки |
| `js-batch-update` | Ограниченный пул, частичные ошибки, дедупликация |
| `sql-activity-indexes` | SQLite EXPLAIN, миграция и сохранность данных |
| `service-launch-contract` | Docker/POM/env и запуск POSIX sh с поддельной JVM; Docker build не выполняется |

Это открытые приближённые dev-задачи, а не воспроизведение корпоративных изменений и не готовый рейтинг инструментов. Подробности и ограничения: [источники задач](docs/CASE_SOURCES.md). Существующие условия и проверки при экспорте в Harbor сохраняются без изменений.

## Проверка интеграции и обновление Harbor

```bash
python -m unittest discover -s tests -v
```

Тесты интеграции запускают настоящие jobs Harbor с поддельным GigaCode, проверяют восемь контрольных решений, параллельные модели, usage, ошибки, тайм-аут с дочерним процессом и чтение результатов через API viewer. Они не вызывают LLM. Реальный GigaCode проверяется первым запуском на целевой машине.

Версия Harbor закреплена в `pyproject.toml` и `flexbench/harbor/__init__.py`. Обновление: изменить обе версии, переустановить зависимости, выполнить тесты и целевой smoke-прогон. Собственного форка Harbor нет.

Документация предыдущего runner и старых артефактов: [LEGACY_RUNNER.md](docs/LEGACY_RUNNER.md). Старые команды сохранены для совместимости; новый путь запуска — `flexbench harbor run`.
