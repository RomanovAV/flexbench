# Массовое обновление выбранных объектов

Исправьте `src/map-limit.mjs` и `src/batch-update.mjs`, сохранив экспорты. Node, ESM, без внешних библиотек и реального HTTP. Контракт специально спроектирован для автономной проверки класса batch-update из frontend-обзора.

`async mapLimit(items, concurrency, worker)`:

- items — плотный массив, worker — функция; иначе Promise отклоняется с TypeError. concurrency — положительное safe integer, иначе RangeError. Все аргументы валидируются до вызова worker, даже при пустом items.
- Ровно один вызов `worker(value, index)` на элемент. Worker может вернуть обычное значение/Promise, бросить ошибку или отклонить Promise.
- Не больше concurrency незавершённых операций одновременно. При достаточном числе элементов запускайте сразу concurrency операций. Освободившееся место сразу занимает следующий элемент, без ожидания всей группы.
- Ошибки отдельных элементов не останавливают очередь. Ответ в исходном порядке: `{status:'fulfilled', value}` / `{status:'rejected', reason}`. Сохраняйте reason как есть. Вход не меняется, несколько вызовов не делят состояние.

`async updateSelected(ids, concurrency, update)`:

- ids — плотный массив непустых после trim строк, update — функция, concurrency валиден по тем же правилам. Проверить **все** ids до первого update. Ошибки ids/update — TypeError, concurrency — RangeError.
- Удалить повторяющиеся id, сохранив порядок первых вхождений. Сравнение буквальное, без нормализации.
- Через mapLimit вызвать `update(id)` ровно один раз для каждого уникального id. Успешная запись ответа `{id, status:'fulfilled', value}`, неуспешная `{id, status:'rejected', reason}`. Порядок первых вхождений, независимо от порядка завершения. Не скрывайте ошибки и не повторяйте запросы автоматически.
- Пустой корректный ids даёт [], update не вызывается, исходный ids не меняется.

Видимая smoke-проверка: `node smoke.mjs`. Можно добавлять свои тесты. Не читайте файлы вне workspace.
